## Build identity

**No APK was produced, and none is expected for this feature.**

Blocker: the audit container has no Android SDK, and it cannot be installed —
the environment's network policy denies `dl.google.com`, which serves both the
Android command-line tools and the Google Maven artifacts for AGP 9.1.0. Two
required build inputs are also absent by design, being gitignored:
`android/local.properties` (supplies `flutter.sdk`, required by
`android/settings.gradle.kts`) and `android/key.properties` (supplies the release
signing config). No signing secret or release setting was changed to work around
this.

F00 changes only Markdown under `docs/`. It alters no Dart, Kotlin, Gradle, or
asset input, so a build from this branch would be functionally identical to a
build of the base commit. Your existing build of
`03323f59835485f3841288e4fd04532a9c6a05bd` **is** the F00 candidate; there is no
separate artifact to install.

### Capture regression

| Action | Expected |
| --- | --- |
| Open Reel from the right-side camera controls | Tools sit in a vertical right-side column bounded by the 3:4 frame; aspect, flash, Layout, Boomerang, AURA all present; framing defaults to **Full** |
| Press and hold the shutter, release, press again | First clip records while held, pauses on release; the next clip appends only after the previous one finalizes |
| Select hands-free 3 s, tap the shutter | Recording stops itself at 3 s; the countdown starts when the camera actually starts recording, not at the tap |
| Set Custom to 1 s, then to 300 s | Both accepted; values outside 1–300 rejected |
| Tap an active hold-mode shutter during a hands-free recording | Pauses that recording |
| Switch front/back between clips, change framing between clips | Both allowed; front-camera clips appear mirrored in the output |
| Rotate the phone during capture | Device orientation stays portrait; landscape output only via the aspect picker |
| Tap Undo after several clips | Removes only the most recent clip |

### Preview and export regression

| Action | Expected |
| --- | --- |
| Record 3 clips with mixed framing, tap Preview reel | Clips play in order; each keeps its own crop, letterboxed inside one canvas; no clip is cropped a second time |
| Compare preview against the saved file | They are the same file — preview plays the rendered output. Note how long Preview takes; that duration is the full-reel re-encode cost F02 must remove |
| Record one clip with the mic blocked or denied, plus one with audio | Reel still exports; the silent clip contributes silence and stays in sync with its video |
| Tap Save reel | Appears in `Pictures/AURA/Videos`; no upload UI appears |
| Tap Save reel twice | Button disables after the first save; no duplicate file |
| Kill the app during capture, relaunch | Clips are **not** restored — this is current documented behavior, not a bug. F15 changes it |
| Background the app mid-recording, return | Earlier clips survive; the interrupted clip is recovered or reported, and the camera reopens |
| Trigger a preview failure (e.g. very low free storage) | An error appears, clips are retained, and Preview can be retried |

## Limitations and exclusions

- **No build, no rendered-output verification, no performance data.** The audit
  environment has no Android SDK and no device. Everything in
  `AUDIT.md` about rendering comes from reading source, not from running it.
- **No native capability matrix.** The plan's R0 asks for Media3 probes across
  animated stills, masks, text, two-video composition, and retimed audio. Those
  probes require a device and belong inside the features that need them. Until
  they run, **no claim about Media3 support on your devices is established** —
  the plan's own `[S4]` note that CompositionPlayer preview is experimental and
  multi-video preview is still in development remains unverified either way.
- **The Media3-versus-FFmpeg decision is open.** F02 must make it explicitly. It
  is a dependency, licensing, and native-module decision, and the current
  FFmpegKit build is GPL-licensed. F00 records the facts and decides nothing.
- **The Flutter SDK used here is not part of the repository** and does not
  survive container replacement. See the last section of `BASELINE.md`.
- **The `integration_test/` suite has never been observed passing in this
  session.** It is recorded as NOT RUN, not as working.
- No music, audio-import, waveform, picker, soundtrack, mixing, ducking,
  voiceover, or beat-detection code was added, and none exists in the repository.

Record the repository as it actually is before the reels motion editor
sequence begins, and fix the one-feature-at-a-time process in writing.

Audit findings that change the plan's assumptions:

- Reel preview is a full FFmpeg re-encode of the whole reel, played back
  with video_player. There is no Media3, no CompositionPlayer and no
  native preview surface anywhere in lib/ or android/. The plan's
  architecture is new work, not an extension of existing code.
- There is no project document: clips are an in-memory list identified by
  index, with no stable IDs, revisions, schema version or asset ownership.

  fps=30, so there is no usable variable-frame-rate timestamp model.

flutter test cases pass, including the six reel cases and the 320x640 at
1.6x text-size case. The integration_test suite, the Android APK build and
